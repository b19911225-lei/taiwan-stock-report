# AI 撰寫規則（ai_output.json）

每天由 Routine 的 Claude session（或 GitHub Actions 備援模式的 Claude API）讀
`history/<日期>/ai_input.json`，寫出 `history/<日期>/ai_output.json`。
寫完執行 `python3.13 run_daily.py validate-ai`，有問題就改到出現 `AI_VALID` 為止。

## 分工：數字由程式算，AI 只寫文字

- 所有數字（價格、漲跌幅、量比、法人張數、進場／目標／停損、RR、評分）都已經由程式算好，放在 `ai_input.json`。
- **只能照抄 `ai_input.json` 裡出現的數字**，可以四捨五入到較少位數（4.82 寫成 4.8 可以），不能自己換算、加總、推估，也不能上網查其他數字。
- 程式會檢查：文字裡的每個數字都要在 `ai_input.json` 找得到。只有不帶單位的 0～20 整數和 60（例如「連買 3 日」「MA20」「60 日高點」）不用；帶 %、倍、元、張、億、萬的數字一律要照抄。不合格的段落會被拿掉，不會送出。
- **不要寫新的目標價、停損價、預估漲跌幅。** 價位一律以 `program_levels` 為準；要提到就照抄。
- 法人資料 `institutional.available` 是 `false` 的股票，不能說外資有買或沒買，只能說「法人資料缺」。
- `missing` 列出的缺漏資料，不要自己補。

## 要寫什麼

1. **stocks**：`candidates` 裡每一檔都要寫一筆，不能多也不能少。
   - `bull_points`：1～3 點做多理由，每點對應一個 `signals` 或指標（例如量比、RSI、外資連買），每點 80 字以內。
   - `bear_points`：1～3 點風險，例如離 MA20 太遠、RSI 過熱、RR 只是剛好過門檻、法人資料缺、所屬主題今天偏弱，每點 80 字以內。
   - `verdict`：只能是「強力做多」「謹慎做多」「中性觀察」「規避」四選一。
   - `confidence`：1～10 的整數。
   - `summary`：2～3 句整合多空，150 字以內。
   - `news_ids`：有引用新聞就填新聞的 `id`（例如 `"N3"`），沒有就空陣列。
2. **highlights**：0～3 則「今日重點」，每則 150 字以內。
   - 把大盤、主題強弱、觀察清單和新聞連起來看，例如「觀察清單有 2 檔屬於散熱電源，主題今天平均 +1.2%；新聞 N2 提到……」。
   - 新聞只寫事實，**不寫分析師看法、目標價、評等**。
   - 兩則新聞說法對不上（例如同一件事數字不同），就兩個都不寫。
   - 沒有相關新聞就只寫數據面的重點，或留空陣列。

## 禁止

- 「保證」「穩賺」「穩贏」「必漲」「必跌」「一定會漲」「一定會跌」「明牌」「內線」「無風險」「零風險」。
- 編造 `ai_input.json` 沒有的事件、財報、法說會內容。
- 推薦 `candidates` 以外的股票。

## 輸出格式

只輸出一個 JSON 物件（Routine 模式直接寫檔，不要加 Markdown 程式碼框）：

```json
{
  "date": "2026-10-16",
  "highlights": [
    {"text": "加權指數收 47,111.26（-0.82%），但散熱電源主題平均 +1.2%，觀察清單 3 檔裡有 1 檔屬於這個主題。", "news_ids": []}
  ],
  "stocks": [
    {
      "stock_id": "6415",
      "bull_points": ["今日量是 20 日均量 2.1 倍（M1），量價同步", "KD 近 3 日黃金交叉（M5）"],
      "bear_points": ["RSI 61.2 已偏高，追價空間有限", "法人資料缺，無法確認外資動向"],
      "verdict": "謹慎做多",
      "confidence": 6,
      "summary": "量能和技術面同步轉強，但籌碼面資料不完整，依程式給的停損 470 控制風險。",
      "news_ids": []
    }
  ]
}
```

`date` 必須和 `ai_input.json` 的 `date` 一樣。
