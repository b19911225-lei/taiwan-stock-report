# AI 撰寫規則（ai_output.json）

每天由 Routine 的 Claude session（或 GitHub Actions 備援模式的 Claude API）讀
`history/<日期>/ai_input.json`，寫出 `history/<日期>/ai_output.json`。
寫完執行 `python3.13 run_daily.py validate-ai`，有問題就改到出現 `AI_VALID` 為止。

## 分工：數字由程式算，AI 只寫文字

- 所有數字（價格、漲跌幅、量比、法人張數、進場／目標／停損、RR、評分）都已經由程式算好，放在 `ai_input.json`。
- **只能照抄 `ai_input.json` 裡出現的數字**，可以四捨五入到較少位數（4.82 寫成 4.8 可以），不能自己換算、加總、推估，也不能上網查其他數字。
- 程式會檢查（標題、盤勢播報、明日觀察、自選股評論也一樣）：文字裡的每個數字都要在 `ai_input.json` 找得到。只有不帶單位的 0～20 整數和 60（例如「連買 3 日」「MA20」「60 日高點」）不用；帶 %、倍、元、張、億、萬的數字一律要照抄。不合格的段落會被拿掉，不會送出。
- 寫「上漲／下跌」或 +／- 的數字，方向要和資料的正負號一致（資料是 -0.82，只能寫「下跌 0.82%」或「-0.82%」）。
- 數值一律用阿拉伯數字；「六百元」「兩成」這種中文數字沒辦法核對，會被拿掉。
- **不要寫新的目標價、停損價、預估漲跌幅。** 價位一律以 `program_levels` 為準；要提到就照抄。
- 法人資料 `institutional.available` 是 `false` 的股票，不能說外資有買或沒買，只能說「法人資料缺」。
- `missing` 列出的缺漏資料，不要自己補。

## 要寫什麼（口吻：財經台盤後節目的主播）

像收費 App 的盤後播報：先講今天發生什麼事，再把大盤、法人、國際股市、新聞和推薦股串成一個故事。
句子短、有重點，不要只把數字排成清單。所有事實只能來自 `ai_input.json`（數字、新聞標題和摘要）。

1. **headline**：一句話標題，40 字以內，像新聞標題。
   例：「外資終止連 10 賣，台股強彈 594.84 點站回 5 日線」。
2. **market_commentary**：盤勢播報，3～5 句、300 字以內。建議順序：
   大盤漲跌與成交金額（`market`）→ 三大法人（`market.institutional_100m`，單位億元）
   → 前一晚國際股市（`us_markets`）→ 今天的新聞事件（`news`，類別「盤勢」「國際」優先）
   → 主題強弱和成交重心（`themes`、`market.top_turnover`）→ 一句帶到今日推薦。
   漲跌家數在 `market.breadth`。資料是 null 或缺的部分就不要提。
3. **stocks**：`candidates` 裡每一檔都要寫一筆，不能多也不能少。
   - `bull_points`：1～3 點做多理由，每點對應一個 `signals` 或指標（例如量比、RSI、外資連買），每點 80 字以內。
   - `bear_points`：1～3 點風險，例如離 MA20 太遠、RSI 過熱、RR 只是剛好過門檻、法人資料缺、所屬主題今天偏弱，每點 80 字以內。
     `tier` 是「次選」「候補」的股票，`tier_note` 寫的就是它沒達標的地方，一定要寫進風險。
   - `verdict`：只能是「強力做多」「謹慎做多」「中性觀察」「規避」四選一。次選、候補不能給「強力做多」。
   - `confidence`：1～10 的整數。
   - `summary`：2～3 句整合多空，150 字以內。`related_news` 有這檔的新聞時，挑一則真的相關的帶進來。
   - `news_ids`：有引用新聞就填新聞的 `id`（例如 `"N3"`），沒有就空陣列。
4. **watchlist**：`watchlist`（使用者的自選股）每一檔寫一筆 `comment`，120 字以內：
   評分、有沒有入選（`pick_rank`）；沒入選就用白話講 `not_selected_reasons`；有相關新聞可以帶一句。
   `unavailable` 有值的股票，照實說資料缺。
5. **highlights**：0～3 則「焦點新聞」，每則 150 字以內。
   - 挑對台股最有影響的新聞，說它和今天的大盤、主題或推薦股有什麼關係。
   - 新聞只寫事實，**不寫分析師看法、目標價、評等**。
   - 兩則新聞說法對不上（例如同一件事數字不同），就兩個都不寫。
6. **watch_tomorrow**：1～3 點「明日觀察」，每點 60 字以內，寫明天要看什麼
   （例如外資是否延續買超、某檔能否守住程式停損）。不預測漲跌、不給新的價位。

## 禁止

- 「保證」「穩賺」「穩贏」「必漲」「必跌」「一定會漲」「一定會跌」「明牌」「內線」「無風險」「零風險」。
- 編造 `ai_input.json` 沒有的事件、財報、法說會內容。
- 推薦 `candidates` 以外的股票（自選股只評論，不推薦）。

## 輸出格式

只輸出一個 JSON 物件（Routine 模式直接寫檔，不要加 Markdown 程式碼框）：

```json
{
  "date": "2026-10-16",
  "headline": "台股收 47,111.26 點，散熱電源逆勢走強",
  "market_commentary": "加權指數下跌 0.82%，成交金額 5,123 億元。外資賣超 120.5 億元，前一晚費城半導體上漲 1.2%。散熱電源主題平均 +1.2% 逆勢領先，今日推薦有 1 檔來自這個主題。",
  "watch_tomorrow": ["外資是否延續賣超", "矽力-KY 能否守住程式停損 470"],
  "highlights": [
    {"text": "加權指數收 47,111.26（-0.82%），但散熱電源主題平均 +1.2%，今日推薦 3 檔裡有 1 檔屬於這個主題。", "news_ids": []}
  ],
  "stocks": [
    {
      "stock_id": "6415",
      "bull_points": ["今日量是 20 日均量 2.1 倍（M1），量價同步", "KD 近 3 日黃金交叉（M5）"],
      "bear_points": ["RSI 61.2 已偏高，追價空間有限", "法人資料缺，無法確認外資動向"],
      "verdict": "謹慎做多",
      "confidence": 6,
      "summary": "量能和技術面同步轉強，但籌碼面資料不完整，依程式給的停損 470 控制風險。",
      "news_ids": []
    }
  ],
  "watchlist": [
    {"stock_id": "4577", "comment": "達航科技評分 45，收盤沒有站上 MA20、動能訊號只有 1 個，今天沒有入選。", "news_ids": []}
  ]
}
```

`date` 必須和 `ai_input.json` 的 `date` 一樣。
